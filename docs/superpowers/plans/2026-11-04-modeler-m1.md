# Modeler, Milestone 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `./vitality lab run modeler <dataset>` builds the modeler image and runs one container that replays a dataset's evidence batch by batch through isolated Claude Code sessions, each checked and committed (or reverted) in the run's own model repo, with complete records.

**Architecture:** A new `modeler/` package holds the session harness (`repo.py` git operations, `claude.py` the command/message/stream, `session.py` one session end to end), the replay (`replay.py`), the playbook, its command `vitality-modeler replay`, and a Dockerfile. The lab gains a host-side `run modeler` that records the run, builds the image and starts the container with plain `docker run`.

**Tech Stack:** Python 3.12+ (image: 3.14-slim as the observer's), uv, pydantic (via usermodel), PyYAML, pytest, pyright (standard), git CLI, Claude Code CLI, Docker.

**Spec:** `docs/superpowers/specs/2026-11-04-modeler-design.md` (amends `docs/superpowers/specs/2026-11-03-user-model-design.md` §8; §9 and §11 there still hold).

## Global Constraints

- Settings and defaults: `MODELER_MODEL=claude-opus-5-5`, `MODELER_EFFORT=high` (one of low, medium, high, xhigh, max), `MODELER_MAX_OPERATIONS=500`, `MODELER_RUN_TIMEOUT_SECONDS=3600`. Lab `--set` short names: `model`, `effort`, `max_operations`, `run_timeout_seconds`.
- Claude Code command, exactly (§5.2): `claude -p <message> --append-system-prompt <playbook> --model <model> --effort <effort> --setting-sources project --strict-mcp-config --permission-mode bypassPermissions --output-format stream-json --verbose`, working directory the model folder; resume adds `--resume <session id>`.
- `ANTHROPIC_API_KEY` is never passed to the container and is removed from the session's environment.
- Container: plain `docker build -f modeler/Dockerfile -t vitality-modeler .` and `docker run --rm` (no Compose; `compose.yaml` unchanged). Mounts only: dataset at `/dataset` read-only, run folder at `/run`, `~/.claude/.credentials.json` at `/home/modeler/.claude/.credentials.json`. `--user <uid>:<gid>` of the host user; `HOME=/home/modeler`.
- Commits in model repos use `-c user.name="Vitality modeler" -c user.email=modeler@localhost`; message `modeler run <id>: <counts>`.
- Session ids: UTC start time `YYYY-MM-DDTHH-MM-SSZ`.
- Code style as `observer/` and `usermodel/`: contract docstrings first, Protocol/`# == Contract ==` where a seam exists, short comments; pyright standard, clean.
- Tests never run a real Claude Code session; they use the fake `claude` of Task 2.

## Review Focus

1. A session that edits an offered evidence file, then fails → after revert the evidence is byte-identical to what was offered (test in Task 3).
2. A batch boundary: a single operations file with more operations than `max_operations` → still offered alone, never skipped forever (test in Task 1).
3. Ctrl-C / SIGTERM during a Claude Code session → the subprocess is killed, the session reverted and recorded as `failed` with "interrupted", and the replay stops with `stopped: interrupted` (tests in Tasks 3 and 4).
4. A dataset whose `user-context.md` is missing, or a captures dataset given to `run modeler` → refused before anything is written (test in Task 6).
5. A stream without a `result` event (Claude Code crashed or was killed) → outcome `failed`, record still written with nulls for tokens/cost (test in Task 3).

### Task 3: `session.py`

**Files:**
- Create: `modeler/vitality_modeler/session.py`
- Test: `modeler/tests/test_session.py`

**Interfaces:**
- Consumes: Task 1 (`repo.*`, `ModelerConfig`), Task 2 (`claude_command`, `session_environment`, `run_message`, `model_index`, `read_stream`); `vitality_usermodel.check.check`.
- Produces:
  - `Outcome = Literal["committed", "reverted", "failed", "limited"]`
  - `@dataclass(frozen=True) class SessionRecord` with the user-model spec §11 fields: `run` (id), `started`, `ended`, `trigger` (`"replay"` in the lab), `operations` (`{"count", "from", "to"}` interaction names), `model`, `playbook` (hash), `outcome`, `attempts` (1 or 2), `check_errors` (list of `"path: message"`), `commit` (or None), `changes` (counts dict, zeros when not committed), `duration_ms`, `input_tokens`, `output_tokens`, `cost`, `transcript` (relative path), plus `detail` (why it failed, "" otherwise); `to_json() -> dict`.
  - `run_session(model: Path, records: Path, config: ModelerConfig, playbook: str, playbook_version: str, *, trigger: str, captures: str | None = None, claude: str = "claude", environ: Mapping[str, str] = os.environ, clock: Callable[[], datetime] = <utc now>) -> SessionRecord | None` — None when nothing is waiting. Steps: refuse (`RuntimeError` listing them) if `foreign_changes`; `choose_batch`; `stage`; start = `head`; run Claude Code (Popen, cwd `model`, env `session_environment`, stdout tee'd to `records/transcripts/<id>.jsonl`, timeout `run_timeout_seconds`); `read_stream`; if `limited` → revert, outcome `limited`; error/exit≠0/timeout → revert, `failed` with detail; else `check(model, start)` — problems → resume once (`resume=session_id`, message: the problems, one per line, and "Fix these, then run vitality-usermodel check."), transcript appended, check again; still problems → revert, `reverted`; clean → `change_counts`, `commit_all(model, f"modeler run {id}: {n} actions, …")`, `committed`. `KeyboardInterrupt` during the subprocess: kill it, revert, append the record with outcome `failed`, detail `interrupted`, then re-raise. Always appends the record as one JSON line to `records/sessions.jsonl`.
