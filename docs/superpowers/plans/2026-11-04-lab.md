# Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `vitality-lab run observer <dataset>` and `vitality-lab list`, reached as `./vitality lab …` on the VM, writing self-describing run folders under `LAB_DIR`.

**Architecture:** A new `lab/` package that imports the observer's core and drives `AnthropicObserver` directly (no loop, no Docker). `record.py` knows git state, run-folder names and `run.yaml`; `observer_run.py` knows the observer stage; `cli.py` wires them and checks preconditions.

**Tech Stack:** Python 3.12, uv, PyYAML, pytest + pytest-asyncio, pyright (standard), git CLI via `subprocess`.

**Spec:** `docs/superpowers/specs/2026-11-04-lab-design.md`

## Global Constraints

- The lab never writes under `vitality-data`; it reads the dataset's `captures/` only.
- Mode is always `direct`. Settings come from `OBSERVER_MODEL`, `OBSERVER_EFFORT`, `OBSERVER_PARALLEL`, `OBSERVER_CALL_TIMEOUT_SECONDS`; `--set` short names are `model`, `effort`, `parallel`, `call_timeout_seconds`, validated by the observer's own `load_observer_config`.
- `LAB_DIR` default: `~/vitality-lab`. Datasets: `$LAB_DIR/datasets/<name>/captures/…`; runs: `$LAB_DIR/runs/<YYYY-MM-DDTHH-MM-SS>-<commit7>[-dirty][-<label>]/` (local time).
- Untracked-file check covers `observer/`, `usermodel/`, `protocol/`, `lab/`.
- A wait of at most 300 s is waited and the interaction retried; a longer wait stops the run.
- Tests make no real API calls. pyright clean; code style follows `observer/` (contract docstrings, short comments).
- Spec addition (ruling): `run.yaml` gains `stopped:` (null, or why the run stopped early) and `not_run:` (list of names) so "recorded as not run, with the reason" has a place. Cost sums the `cost` field of each call record.

## Review Focus

1. Ctrl-C mid-run → `run.yaml` still finished with the remaining interactions as `not_run` and `stopped: interrupted` (test in Task 2).
2. An interaction asked to wait forever (rate limited every time) → not an infinite loop: after 5 waits it is a failure (test in Task 2).
3. A label with spaces or slashes → refused before anything is written (test in Task 1).
4. Running from a repo with only an uncommitted edit to `prompt.md` → `dirty: true`, `changes.diff` contains it, and `prompt.md` copy is the edited text (tests in Tasks 1 and 3).
5. `--set parallel=0` or `--set mode=batch` → refused with the observer's message / "unknown setting" (test in Task 2).

### Task 2: `observer_run.py`

**Files:**
- Create: `lab/vitality_lab/observer_run.py`
- Test: `lab/tests/test_observer_run.py`

**Interfaces:**
- Consumes: `ObserverConfig`, `load_observer_config` (`vitality_observer.config`); `interactions` (`vitality_observer.work`); `Observer`, `Outcome` (`vitality_observer.provider.interface`).
- Produces:
  - `SETTINGS = ("model", "effort", "parallel", "call_timeout_seconds")`
  - `observer_settings(environ: Mapping[str, str], overrides: Sequence[str]) -> ObserverConfig` — takes the four `OBSERVER_*` variables from `environ`, applies `name=value` overrides as `OBSERVER_<NAME>`, validates via `load_observer_config`, forces `mode="direct"`. Raises `ValueError` for a malformed override (`no "="`) or a name not in `SETTINGS` (`unknown setting 'mode'; one of model, effort, parallel, call_timeout_seconds`).
  - `settings_record(config: ObserverConfig) -> dict` — `{model, effort, parallel, call_timeout_seconds}`.
  - `@dataclass class RunResult: ok: int; failures: dict[str, str]; not_run: list[str]; stopped: str | None; cost_usd: float`
  - `MAX_WAIT_SECONDS = 300`, `MAX_WAITS = 5`
  - `async def run_observer(config: ObserverConfig, observer: Observer, *, sleep: Callable[[float], Awaitable[object]] = asyncio.sleep, echo: Callable[[str], None] = print) -> RunResult` — `config` already points `captures_dir` at the dataset and `model_dir`/`state_dir` at the run folder. Observes `interactions(config)` in chunks of `config.parallel`; per outcome: ok → count; `wait_seconds` set and ≤ 300 → sleep the longest such wait in the chunk, retry those items (an item waiting a 6th time becomes a failure `"kept being asked to wait: <detail>"`); `wait_seconds` > 300 → stop: that item and all not yet done go to `not_run`, `stopped = detail`; otherwise a failure `name → detail`. `asyncio.CancelledError` → the in-flight and remaining items go to `not_run`, `stopped = "interrupted"`, and the result is returned. Cost sums `outcome.record.get("cost") or 0` over all outcomes. `echo` gets one line per outcome: `ok   <name>` / `fail <name>: <detail>` / `wait <name>: <detail> (<n> s)`.

  - `test_all_ok`: 5 items, parallel 2 → batches `[2,2,1]`, `ok == 5`, `cost_usd == pytest.approx(0.10)`, `stopped is None`.
  - `test_failure_recorded_and_run_goes_on`: one fails `"bad reply"` → `failures == {name: "bad reply"}`, `ok == 4`.
  - `test_short_wait_retried`: one returns wait 30 then ok → `sleep` called with 30, `ok == 5`.
  - `test_endless_wait_becomes_failure`: one always waits 30 → after 5 sleeps a failure starting `"kept being asked to wait"`.
  - `test_long_wait_stops`: item 3 of 5 waits 21600 `"out of API credits"` (parallel 1) → `ok == 2`, `not_run == [item3, item4, item5]`, `stopped == "out of API credits"`.
