# Docker Compose for the VM — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the server and the observer with Docker Compose: settings from `.env`, one command per package, a `./vitality` helper, and no install scripts or systemd units.

**Architecture:** Each package reads its settings from environment variables and has one command with subcommands (`vitality-server serve|status|healthcheck`, `vitality-observer run|status`). A Dockerfile per package builds an image from the checkout; `compose.yaml` runs both as the owner, with bind mounts under one data folder and the owner's Claude login mounted into the observer. `./vitality` wraps the everyday `docker compose` commands.

**Tech Stack:** Python 3.14 (requires ≥3.12), uv, FastAPI/uvicorn (server), Claude Code (observer), Docker 29 / Compose v2, bash.

**Spec:** `docs/superpowers/specs/2026-10-29-compose-design.md`

## Global Constraints

- Compose services are named `server` and `observer`; their commands are `vitality-server serve` and `vitality-observer run`, written visibly in `compose.yaml` (`command:`).
- Environment variables, exactly: `VITALITY_DATA` (compose default `${HOME}/vitality-data`), `VITALITY_UID`, `VITALITY_GID` (compose defaults 1000); `SERVER_DATA_DIR` (default `/data`), `SERVER_PORT` (8100), `SERVER_ALLOWED_CLIENTS` (comma-separated, default empty); `OBSERVER_CAPTURES_DIR` (`/captures`), `OBSERVER_MODEL_DIR` (`/model`), `OBSERVER_STATE_DIR` (`/state`), `OBSERVER_BATCH_SIZE` (10), `OBSERVER_CONTEXT_SIZE` (15), `OBSERVER_CALL_TIMEOUT_SECONDS` (600), `OBSERVER_MODEL` (empty = Claude Code's default).
- Host data layout: `$VITALITY_DATA/server/` (captures/, tmp/, index.sqlite), `$VITALITY_DATA/model/` (observations/), `$VITALITY_DATA/observer/` (calls.jsonl, skipped.txt).
- Container mounts: server `/data` ← `$VITALITY_DATA/server` (rw); observer `/captures` ← `$VITALITY_DATA/server/captures` (ro), `/model` ← `$VITALITY_DATA/model`, `/state` ← `$VITALITY_DATA/observer`, `/home/observer` = tmpfs (HOME), `/home/observer/.claude` ← `${HOME}/.claude`, `/home/observer/.claude.json` ← `${HOME}/.claude.json`; both `/etc/localtime:ro`; server `/var/run/tailscale` ← host `/var/run/tailscale` (the **directory**, so a restarted tailscaled's new socket is seen).
- Both services: `user: "${VITALITY_UID:-1000}:${VITALITY_GID:-1000}"`, `restart: unless-stopped`, `read_only: true`, tmpfs `/tmp`, `security_opt: [no-new-privileges:true]`, `cap_drop: [ALL]`, json-file logging `max-size: 10m`, `max-file: "3"`. Server: `network_mode: host`; healthcheck `vitality-server healthcheck` every 30 s.
- Images built from the checkout (`build:` with the repo root as context). Pinned via build args: Claude Code version, tailscale version, uv version. Claude Code installed at `/usr/local/bin/claude`, `DISABLE_AUTOUPDATER=1`.
- Error messages for settings name the variable: `SERVER_PORT must be an integer from 1 to 65535, got 'abc'`.
- Components keep their `# == Contract ==` sections; plain modules are signatures + docstrings, public first. No `Co-Authored-By` / "Generated with" lines in commits.
- `uv run pytest -q` and `uv run pyright` (0 errors) pass in each package touched.
- Never touch the VM, the running laptop services, `~/.local/share/vitality*` or `~/.config/vitality`; never run a real `claude -p` (except Task 6, done by the controller with the owner).

## Review Focus

1. **Bind-mount sources missing at `docker compose up`** → Docker creates them root-owned and the containers (running as the owner) cannot write; `./vitality setup` must create every source first, and refuse when the owner's Claude login (`~/.claude/`, `~/.claude.json`) is missing. Covered in Task 7.
2. **tailscaled restarts on the VM** → a socket file bind-mounted on its own goes stale; mount `/var/run/tailscale` as a directory. Covered in Task 5's compose and its smoke test.
3. **`~/.claude.json` replaced by rename** inside the container breaks a single-file bind mount; Task 6 checks it with the owner and switches to the fallback mount if needed.
4. **`SERVER_ALLOWED_CLIENTS` written as `laptop, phone` or left empty** → names are stripped, empties dropped; empty means every upload is refused (the server warns at start). Covered in Task 1's tests.
5. **`./vitality upgrade` on a checkout that is not on `main`, has local changes, or has diverged** → stop before building, saying why; nothing is rebuilt. Covered in Task 7.
